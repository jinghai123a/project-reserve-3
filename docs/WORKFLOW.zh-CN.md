# 方案驱动的云端协作

## 从目标到交付

1. 负责人读取项目目标、现有实现、输入版本和检查点，确定可验证的完成条件。
2. 在现有方案中写明当前阶段、任务依赖、实际参与岗位和需要触发的规则。
3. 后勤复用已有服务器、平台功能、容器、插件和成熟组件，补齐本阶段实际需要的主工具和备用路线。
4. 协调器按方案中的任务图派发；每项任务带目标、版本、写入范围、产物和验收命令。
5. 执行者完成业务，独立验证者检查真实产物和运行结果，失败只退回受影响部分。
6. 阶段结束保存证据、评分依据、未完成项、下一步及恢复入口；交付完整可用结果和配置清单。

## 五类职责与后勤

| 职责 | 产物 |
| --- | --- |
| 产品与研究 | 业务目标、来源、用户流程和完成条件 |
| 架构与方案 | 主方案、关键依赖、备用路线和切换条件 |
| 设计与体验 | 可操作界面、组件状态和可编辑资产 |
| 工程与交付 | 代码、配置、集成、部署与恢复入口 |
| 独立质量验证 | 行为证据、回归结果、可复现缺陷 |
| 后勤支援 | 任务需要的工具、环境、认证引用和可用性记录 |

组织角色在 `company/organization.json`，实际角色指令在 `.codex/agents/`。负责人直接管理执行者，只有工作包仍可独立拆分且有收益时才增加一级子任务；总并发采用当前运行配置。

## 规则如何触发

| 当前工作 | 触发内容 |
| --- | --- |
| 参数或小范围文档修改 | 原功能保留、差异与必要核验 |
| 联网研究 | Firefox、Google Chrome、Microsoft Edge 实际检索；Wikipedia 条目和参考文献；追溯原始来源 |
| 界面交付 | 设计、关键操作路径、错误状态和可读性 |
| 业务实现 | 选定工程岗位、接口集成、受影响回归 |
| 安全排查 | 具体位置、行为、证据和最小修复 |
| 云端部署 | 目标环境配置、健康验证、备份恢复与运行交接 |

在现有任务 `goal` 或交接中记录适用规则及触发理由。未涉及项为不适用，后续阶段项为待触发。资料来源与浏览器分别记账：同一篇文章被三个浏览器打开，仍是一条资料。

研究记录包含浏览器与版本、查询时间、链接、发现、差异和未完成核验。浏览器缺口交后勤处理，其他任务继续推进。

## 长任务与局部故障

项目状态保存在本项目 `automation/state`，工作区与产物保存在该项目的持久存储。恢复时核对项目、仓库、源码版本、阶段、输入和下一步。

同因重复两次或三次无进展时，保留关键日志并诊断根因，再局部修复或切换有依据的路线。独立就绪任务继续运行。业务失败、环境失败、调度与回执故障分别记录。

当前调度器已经按计划任务与依赖运行，采用单一共享工作区写入者；专业角色配置只提供可调用能力。

## 阶段记录和评分

使用 `company/stage-report.template.json`，将实际记录保存在业务项目 `.company/stages/<stage-id>/`。填入真实参与者、项目身份、输入版本、产物引用、验证结果、未完成项、下一步和恢复方式。

| 维度 | 权重 | 依据 |
| --- | ---: | --- |
| 目标完成 | 35 | 该阶段约定结果 |
| 正确性与原功能保留 | 25 | 业务行为与回归 |
| 验证证据 | 20 | 与实际版本对应的检查 |
| 效率 | 10 | 重试、返工与实际消耗 |
| 交接恢复 | 10 | 下一执行者能否准确接手 |

尚未评价的分项保留 null，并写原因与证据覆盖。关键功能失败单独呈现；独立审核者核对证据。模板是记录格式，实际判断来自运行验证与审核。

改进顺序：失败案例→根因→小范围修改→历史案例与保留测试比较→采用或回退。已验证经验再进入可复用知识；项目原始资料保留在项目内。

## 交割清单

交付可用入口、完整产物、实际改动、验证结果、版本与回退方式。配置清单分别列已完成配置、用户需完成的一次性操作、尚待完成项及验证方式。无需用户操作时直接写明。
